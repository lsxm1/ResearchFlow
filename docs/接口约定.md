# API与数据约定 · v0.1

开发入口 `/api`；Vite代理到127.0.0.1:8000，浏览器不需要跨域直连。精确请求/响应以运行中的 `/docs` 和 `/openapi.json` 为准。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | /api/health | 健康、模型配置状态（不泄露密钥）、OCR可用标志 |
| GET | /api/documents | 所有文献与解析进度 |
| POST | /api/documents | multipart `file`，返回document及exact_duplicate |
| GET | /api/documents/{id} | 单篇详情，包含duplicates数组 |
| DELETE | /api/documents/{id} | 删除文献及索引，204 |
| GET | /api/documents/{id}/file | 原始PDF，inline；可附`#page=N` |
| GET | /api/documents/{id}/pages/{page} | 页文本、页面尺寸和块列表 |
| POST | /api/documents/{id}/retry-ocr | 待识别文献重新入队，返回 202 |
| POST | /api/tasks | `{question, document_ids}`，返回任务id及queued状态 |
| GET | /api/tasks | 最近30条任务 |
| GET | /api/tasks/{id} | 状态、工具事件、生成结论与证据 |

document状态：queued → parsing → ready / partial / needs_ocr / failed。partial指存在需OCR的图像页；教材空白页不自动计为需OCR页。

task状态：queued → running → completed / failed。result.mode为evidence_only / model_assisted / error。**configured仅指存在模型配置，不表示服务已经连通**。

证据形状：

```json
{"id":"chunk_id", "document_id":"uuid", "page":5, "text":"原文片段", "bbox":[70,100,520,200], "score":2.3, "file_url":"/api/documents/uuid/file#page=5"}
```

页码是从1开始的PDF物理页；不是教材印刷页码。bbox是PyMuPDF的左上原点页坐标，单位为point。它描述原始文本块，切分后可能多个chunk共用bbox。PDF.js集成需处理缩放和旋转转换，不能直接当CSS像素。

页文本与新证据的 `source` 为 `native` 或 `ocr`。多选文献时，每篇独立返回最多三条初次检索候选。

claims形状：`{text, source_id, quote}`。source_id必须对应实际返回的证据，quote必须是其text内的精确连续子串。该检查不代表语义真实性验证。

规范：不改变现有路径或响应字段；新增字段兼容旧调用。新服务独立文件，路由统一在main.py注册。所有外部请求设置超时，不返回密钥和本机路径。新存储字段提供迁移方案。
