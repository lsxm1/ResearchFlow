# 省赛部署与提交

参赛功能基线为 `75fa172`。Railway 部署使用 `0c9479f`，其应用代码与功能基线一致。

## 源码仓库

参赛仓库为 [lsxm1/ResearchFlow](https://github.com/lsxm1/ResearchFlow)，主分支为 `main`。离线时可在解压目录运行下列命令恢复源码及 Git 历史。

```powershell
git clone '.\参赛材料\ResearchFlow-Git.bundle' '.\ResearchFlow-Git'
```

正式提交前，用具备评审权限的账号打开仓库并检查 README、依赖锁和 `.env.example`。真实 `.env`、API 密钥和用户数据留在运行环境。

## 公网演示

参赛版本已部署到 [Railway](https://researchflow-production-c46afc77.up.railway.app/)。评审用户名为 `reviewer`，口令随赛事表单提交。线上使用证据模式和实例临时存储。已验证登录、论文上传、对比、高亮、报告导出以及公开替代样本解析。评审期可用性取决于免费额度与实际用量。

## 自托管复现

1. 在有 Docker Compose 的目标主机检出同一份源码。在项目根目录建立 `.env`，设置独立的 `RF_DEMO_PASSWORD`。需要展示生成式问答或翻译时，再配置容器可访问的模型接口和模型名。
2. 在目标主机运行 `docker compose up -d --build`。Compose 默认只把应用端口映射到主机的 `127.0.0.1:8000`。使用目标主机的 HTTPS 反向代理把参赛域名转发到这个端口。
3. 从另一网络打开公网 HTTPS 地址，用 `reviewer` 和评审口令验证。核对 PDF 上传、论文对比、原文高亮和报告下载。开启模型时再核对一次带出处的问答。
4. 检查匿名访问会收到登录提示。评审账号和口令填在赛事提交页面的指定位置。评审期间保持服务可用。

Windows 本机已完成带口令的空库验收。取得组委会原始样本后可复验。Windows 的 `-LocalModel` 安装流程与容器部署是两个入口，容器的模型服务按 `.env` 配置。
