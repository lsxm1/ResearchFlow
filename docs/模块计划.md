## 路线

研究意图 → 文献导入/检索 → 解析入库 → 检索证据 → 分析与校验 → 图谱/对比/综述/图表 → 原文核查。

架构：React+TypeScript → FastAPI → SQLite+磁盘PDF；解析与任务分离执行。模型通过单独适配器连接，先不决定本地或云端，不训练模型。所有业务事实尽量绑定document_id、页码、chunk_id、原文引句；不能靠提示词声称“零幻觉”。

## 我与豆包的协作

Codex：核心接口与数据约定、Agent证据链、检索设计、难点审查、集成验收。

豆包：按单个任务书完成有边界的实现，整理额外文献、运行回归、补截图及文档草稿。不要在同一时间让两个Agent修改同一文件。先提交当前状态，再交接；完成后只给文件清单、验证命令结果、已知问题，不往聊天粘全仓代码。

`豆包任务01-OCR.md` 留作 OCR 开发记录。接下来可分别交接 PDF.js 阅读器、文献元数据检索和 CSV 图表。

## 当前明确限制

- PDF文本块排序不是通用双栏/公式语义还原器；正文指纹不是语义Embedding。
- 检索为词面BM25，复杂中文意图与跨文证据覆盖仍有限；尚无重排与检索充分性评估。
- 模型模块是“受限补充检索→生成→引句核验”的基础流程，未实现原生Function Calling、复杂动态规划、多Agent或长期记忆。
- 原生PDF阅读器只支持页级跳转；保存的bbox尚未在界面高亮。
- 逐页解析控制跨页内存占用，但尚无恶意PDF隔离、并发压测或生产资源监控。单个异常页面仍可能消耗较多资源。
- 无登录与公网访问控制；当前只供本机开发。后台执行器为进程内队列，不能作为多实例部署队列。
