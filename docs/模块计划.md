# ResearchFlow 赛题范围与验收

ResearchFlow 的参赛目标是**基于大模型和 Agent 的全流程科研助手**。用户输入研究意图，系统规划任务、调用工具，从文献检索和导入推进到精读、溯源问答、引用分析、综述和写作绘图。用户可以核对中间证据和最终成果。

范围依据是参赛者提供的赛题原文中的「命题范围」「测试数据集与验证用例」「评审标准」和「比赛环境」。报名与封版时间按个人中心通知确认。公开的校赛通知也区分了「AI创新应用」与「AI大模型创新应用」两个赛道。[东莞理工学院赛道通知](https://cs.dgut.edu.cn/info/1034/19118.htm)

## 六个必做模块

下表的交付验收依据赛题要求。实现可以逐步推进，已经实测的部分和仍需实现的部分分别记录。

| 模块 | 目前有的基础 | 提交前应验收的功能 |
|---|---|---|
| M1 PDF 管理与细粒度解析 | 单篇与批量上传、删除、逐页解析、英文扫描件 OCR、正文词组相似提醒。替代版扫描论文与 541 页教材已实测 | 支持文献管理和基于正文语义的版本识别。改名的 v7、v1 仍能匹配，用户可保留或替换版本并看到新旧建议。用原生 PDF、扫描 PDF 和长教材验证标题、作者机构、摘要、三级目录、表格、图、LaTeX 公式、参考文献和附录的结构化呈现。长文档分块索引、按需加载并记录资源占用。 |
| M2 抗幻觉问答与跨文献推理 | BM25 候选、按篇展示证据、原文页码和块坐标。模型适配器与引句校验已编码，真实模型待实测 | 接通真实模型，使用词面和语义检索回答单篇细节问题，并跨多篇推理。按超参数、硬件、BLEU 和完整引用测试正确性，结论可跳到原文位置。缺证据时提示范围或触发补查。跨文对比呈现共同点、差异和不可直接比较的条件。 |
| M3 版式感知阅读与联动翻译 | 原始 PDF、提取文本切换和页码跳转 | 保持原文版式，目录可定位，正文引用标号与参考文献双向跳转。支持局部翻译、整篇翻译导出和中英对照双向滚动。公式和代码保留原文。 |
| M4 自动检索、追踪和推荐 | 待开发 | 按标题或参考文献调用学术 API 检索并下载可用 PDF，结合引用上下文筛除低相关条目并说明依据。定期更新 arXiv 主题，按用户文献库与偏好推荐，优先提示有可复现代码的论文。推荐有理由、有赞踩反馈，偏好数据可按用户扩展。 |
| M5 引用图谱、综述和前沿探索 | 待开发 | 用约 20 篇实际文献构建可交互局域引用图，每条边可核对。用图算法区分基石与衍生论文。基于图谱生成带引用的短综述，提取 Future Work 并结合后续研究筛查已解决方向，标明检索范围及尚无充分证据的判断。 |
| M6 学术写作和数据可视化 | 待开发 | 根据研究意图生成包含 Abstract、Introduction、Related Work 和真实 References 的论文框架。生成可运行的架构图脚本。上传 CSV 后生成表格、折线图、柱状图、三维雷达图和基于数据的图注，按赛题用例核验绘图脚本输出。中文摘要或正文支持学术英文翻译。 |

## Agent 和全流程验收

Agent 需要根据意图拆解任务，在允许的工具范围内调用文献检索、证据查询、引用分析和成果生成。遇到缺文献或缺证据时，能决定补查、调整步骤或返回未解项。界面展示实际工具调用、执行状态、证据和可核对输出。真实模型通过现有适配层接入，模型来源和费用单独决定。词组匹配、独立片段列表和引句存在校验分别是版本识别、对比推理和证据验证的基础。

演示主线采用「从研究问题到论文提纲」。输入一个研究意图，Agent 检索并导入相关论文，在联动阅读中核查原文，生成跨文对比和局域图谱，再基于引用写出 Related Work 和论文提纲，结合 CSV 生成实验图及图注。组会对比可以演示问答和溯源，作为其中一段。

原生 PDF、扫描版和 541 页长教材走真实上传流程。使用预置文件验证去重、OCR、结构化解析、索引和按需加载。当前的公开替代数据用于开发验收，取得组委会数据后再按同样流程复核。跨文推理用不同论文，v1 和 v7 用于版本测试。技术优先级参考评分中的 Agent 与大模型技术深度 35% 和科研场景创新性 25%，并为其余模块保留开发和联调时间。

## 开发顺序与分工

1. 优先闭合一条真实 Agent 路径，从缺文献触发搜索和导入，到混合检索、跨文对比和原文核查。同步补齐 OCR、长文解析和版本管理的欠项。
2. 阅读器、追踪推荐、引用图谱和写作绘图按接口推进。重复实现和测试资料整理可分给豆包。Codex 负责 Agent 规划、证据接口和集成验收。已有 OCR 的历史任务书留在仓库供查阅。
3. 逐项运行六模块验收，再联调公网演示和材料。优先复用成熟组件，控制支持的文献来源、模型选型和界面复杂度。进度表按实际功能记录已通过和待验收项。

按赛题材料中的 11 月 18 日提交目标倒排。11 月 12 日前验证首条 Agent 路径，13–15 日集中补齐和联调六模块，16–17 日验证部署并完成文档和视频，18 日预留提交时间。进度不足时先压缩界面打磨和可选扩展，必做缺项按验收表如实记录。

现有工程继续使用 React、FastAPI、SQLite 和磁盘 PDF。证据沿用文档 ID、物理页码、文本块 ID、坐标和引句。上传和解析的后台队列目前适用于本机开发，正式部署前验证并发、超时和故障恢复。可复现性、图谱性能、联动交互和任务进度也纳入评分检查。

## 提交前检查

- GitHub 或 Gitee 仓库有评审访问权限，保留真实 Git 历史。README、依赖、环境变量和部署步骤能复现作品，文档记录 AI 协作和开源组件贡献。
- 公网演示在评审期间可用。若需登录，提供评审账号。
- 普通话讲解视频为 5–8 分钟、至少 1080p 的 MP4。技术 PDF 不超过 30 页，覆盖架构、AI 方案、创新点、测试和部署。
